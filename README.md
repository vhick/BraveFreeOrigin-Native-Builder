# Brave Free Origin — source-built NATIVE Portable Builder b1r3

**Resolved mode: NATIVE only.** This kit uses a compiled Windows .NET Framework executable to **embed and execute the real upstream PowerShell GUI source in-process**, with an application-specific storage adapter. It is not a Chromium/Brave browser and does not recompile PowerShell syntax into native machine instructions. It relies on Windows' bundled PowerShell 5.1 runtime. The Windows executable is directly runnable without BAT, external PS1, PortableApps root launcher, or manager. It is unsigned.

**Read this before running:** The upstream tool is a Brave *debloater*. User-directed operations intentionally change `HKLM\SOFTWARE\Policies\BraveSoftware\Brave`, plus optional hosts/updater/browser scriptlet state. That cannot be isolated in `Data` without removing its core functionality. The utility's settings, logs, policy backups, scriptlet backups, and temporary shortcuts are redirected into the portable folder. Existing Brave browser profile stays at its existing location and is not collected.

## Build with GitHub Desktop (no local compiler)

1. On GitHub, create a **new empty repository** called e.g. `BraveFreeOrigin-Native-Builder`. Do **not** fork upstream. Public repo can use the normal GitHub-hosted public Action runner; choosing private can be subject to account minutes limits.
2. In GitHub Desktop: **File > Clone repository**, choose the new repo, then **Show in Explorer**.
3. Extract **the contents** of this kit into the root of the cloned repo; make sure the hidden `.github/workflows/native-build.yml` file is included. Never put the kit in an extra nested directory.
4. GitHub Desktop: enter commit summary `Add Brave Free Origin native source builder b1r3`, click **Commit to main**, then **Push origin**.
5. On GitHub: **Actions > Brave Free Origin - Build NATIVE Portable from Source > Run workflow**. Leave `upstream_version` at `latest` (or specify a published stable version such as `v2.0.2`). `publish=true` publishes after validation.
6. Open the job logs. Check **Resolve stable upstream tag**, **Compiled executable runs real upstream application sandbox self-tests**, **Publisher dry-run** and **Publish**. If one fails, the release is not valid.
7. Open **Releases** in **your builder repository** (not upstream). Download `BraveFreeOrigin-NativePortable-vX.Y.Z-b1r3-gXXXXXXXX-pXXXXXXXX.zip` and its `SHA256SUMS.txt` generated by the pinned publisher. Verify SHA-256 before extraction.
8. Extract to a **writable** folder. Start **BraveFreeOrigin.exe** directly. Accept UAC when using GUI; apply changes only after reading the preview. `Data/settings.json`, `Data/logs/`, `Data/Backups/`, `Data/ScriptletBackups/`, and `Data/TempShortcuts/` are local data paths.
9. To upgrade: stop the app, back up its entire directory, extract the next ZIP to **a different folder**, and copy the **existing Data directory** to the new folder. The new ZIP contains an empty Data directory, so do not overwrite an existing Data accidentally.
10. To roll back: use your full backup of the previous app and Data. If Brave system settings were modified, use the **app's Restore stock** or your saved registry backup as appropriate; restoring binaries is not the same as restoring Brave policies.

## Kit structure

- `.github/workflows/native-build.yml`: one Windows GitHub Actions job, manual dispatch, upstream source discovery, adapter, real PE compilation, sandbox application tests, ZIP, independent validation and shared publisher.
- `host/BraveFreeOriginHost.cs`: transparent C# in-process Windows PowerShell host, same-EXE UAC, single-instance guard, embedded plain upstream source resource.
- `host/app.manifest`: `asInvoker`; C# host prompts UAC only for real GUI use, allowing unelevated sandbox tests.
- `scripts/resolve_source.py`: stable release semver resolution, remote tag commit verification and source hashes; no silent `main` builds.
- `scripts/adapt_source.py` and `scripts/patch_expert.py`: fail-closed changes for settings, logs, backups, local scriptlet recovery, temporary shortcuts, locale paths, UAC, and test handling.
- `scripts/build_native.ps1`: uses the official Windows .NET Framework C# compiler and the Windows PowerShell 5.1 engine assembly (no third-party compiler dependency).
- `scripts/test_compiled.ps1`: executes the real **compiled executable** with upstream's sandbox self-tests, then the upstream locale and bootstrap suites; fails on nonzero exit or report failures.
- `scripts/validate_native.py`: PE validation, embedded-source check, ZIP integrity, source identity, locale coverage and wrong-mode rejection.
- `tests/test_builder.py`: offline fail-closed adapter and ZIP validation regression tests.
- `docs/`: source findings, limitations, setup and test-report guide.

## Version and safety policy

- Stable release `latest` is resolved numerically from the upstream GitHub API; alpha, beta, RC, nightly, unpublished versions, non-semver tags and `main` are refused.
- Git fetch uses official GitHub HTTPS; the fetched commit is compared to the remote signed/unsigned Git tag commit (provenance is Git object identity, **not** proof of code safety). Upstream source SHA-256 is recorded in `build-identity.json`.
- Upstream source is embedded as clear ASCII text in the PE resource; no downloaded script is evaluated at runtime and no obfuscation/AV-evasion is used.
- The only shared packaging integration is the **verified release publisher** `vhick/portable-release-publisher@v1.1.1`. The `Portable-Package-Builder` is intentionally not used in NATIVE mode.
- ZIP released only after headless source, Windows compile, source self-test and static package checks. **Those tests do not prove interactive GUI functionality or host-state cleanliness**; follow `docs/MANUAL-WINDOWS-TESTS.md` before marking USER-CONFIRMED.
- The app does **not** copy credentials/browser profiles or delete any existing Brave installation. The utility's advanced actions can modify real Brave/Windows configuration if and only if the user requests them.

For troubleshooting and known caveats, read `docs/AUDIT.md` and `docs/MANUAL-WINDOWS-TESTS.md`.

### Repeat build and releases

The action checks whether the exact upstream SHA and builder package hash already has an existing publisher-managed release. If so it skips recompilation and republishing rather than overwrite the asset with changed compiler timestamps. A changed adapter/host/build implementation produces a different `pXXXXXXXX` release identifier. ZIP metadata timestamps are normalized; compiled .NET PE bytes are **not** claimed byte-for-byte reproducible.


## b1r2 fix (2026-11-10)

GitHub Actions b1r1 failed before C# compilation at the Windows PowerShell 5.1
parser stage, reporting two `Unexpected token '}'` errors.  The UAC adapter's
`Add-Type` search accidentally stopped inside the upstream `catch` block
instead of after the whole elevation block, leaving two unmatched `}`.  b1r2
matches the full consecutive WinForms/Drawing initialization boundary, keeps
all GUI initialization, and fails closed if it changes.  An explicit regression
fixture models both occurrences of `Add-Type`.  Parser diagnostics now include
actual line and column numbers for future errors.  This correction was tested
offline, but actual Windows compilation and GUI behavior require GitHub Actions
and manual Windows acceptance, respectively.


## b1r3 fix (2026-11-10)

The b1r2 GitHub Actions job successfully resolved the upstream v2.0.2 source,
patched it, and advanced past Windows compilation. It then failed copying the
first locale (`ar.json`): Windows PowerShell 5.1 does not permit three positional
arguments to `Join-Path`. The locale-copy loop now resolves the directory
first and then joins each filename separately with named `-Path`/`-ChildPath`.
A new regression test checks that PowerShell-5.1-compatible layout.
Successful Windows runtime and published releases must still be confirmed by a
new CI run and interactive manual tests.

The first Windows workflow step additionally runs a PowerShell 5.1 smoke test that executes the locale copy loop against `ar.json`, `fr-FR.json`, and `zh-CN.json` in a temporary Unicode/space-containing folder.
